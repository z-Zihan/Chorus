# AgentLink 产品审计

> 审计日期：2026-08-01  
> 审计对象：v0.1 开发者预览版  
> 判断标准：以用户能否完成任务为准，不以类型、接口或底层模块是否存在为准。

## 结论

AgentLink 已经证明“把 CLI Agent 放进聊天界面”在技术上可行，但还没有证明“普通 CLI 用户打开应用就能使用”。当前最严重的问题不是缺少更多 Adapter 或更多基础设施，而是首个价值时刻被配置文件挡住了。

**唯一正确的下一优先级是 CLI 自动检测与零配置首启。** 在这条路径完成之前，i18n、主题、跨 Hub、更多协议等工作都不能取代 P0。

## 五项价值主张审计

| 价值主张 | 结论 | 用户视角判断 | 实现证据与缺口 |
|----------|:---:|--------------|----------------|
| 1. CLI 管理工具 | ⚠️ | 已配置的 CLI 可以在可视化界面聊天，也能查看状态和部分设置；但用户必须先知道命令、参数和输出格式，再手写配置。 | `CliAdapter` 已实现；`config.ts` 只读取配置；全仓没有 PATH 扫描、可执行文件解析或检测 API。自动检测是 P0。 |
| 2. 应用内安装 | ❌ | 用户无法在 UI 浏览、安装或卸载 Agent。后端 `POST /api/agents` 不是安装体验。 | 路由支持注册/删除，但前端只有编辑已有 Agent 的设置面板，没有创建入口或 Catalog；数据库中的 UI 注册项也没有在重启时重新装载到 Registry。 |
| 3. 多 Agent 群聊 | ❌ | 用户不能创建一个可用的多 Agent 房间、选择成员并观察真实路由。 | 有 A2A Bus、线程 UI、`group` 字段和 Relay Room API，但会话创建只绑定一个 Agent，前端没有群聊/成员管理；桌面 Hub Client 未接通 Relay。底层存在不等于群聊可用。 |
| 4. 不用群聊也有价值 | ⚠️ | 单 Agent 流式聊天、本地历史、创建/删除会话和部分 Agent 设置已可用，这是当前最扎实的价值。 | 缺少自动发现、会话重命名/搜索/导出/归档、Agent 与会话切换；空状态不能把用户带到可发送消息的状态。 |
| 5. 低认知负担 | ❌ | 新用户打开无配置版本后会看到 0 个 Agent，仍可创建一个无 Agent 的会话，但无法发消息，也没有修复向导。 | `loadConfig()` 无文件时返回 `agents: []`；`index.ts` 只为配置中的首个 Agent 建默认会话；前端只加载列表，没有 onboarding 状态机。 |

## 关键问题的直接回答

### 是否实现 AI CLI 自动检测？

**没有。P0。** 当前只会注册 `agentlink.config.ts` 的 `agents` 数组。没有扫描 PATH、常见安装路径、Windows `PATHEXT`，也没有安全的 `--version` 探测、去重、缓存和重新扫描入口。

### 是否真正零配置？

**没有。** 服务端可以在没有配置文件时启动，但此时没有可用 Agent。技术进程“启动成功”不等于用户“可以完成第一次对话”。真正的零配置必须至少做到：发现一个 CLI、判断是否可用、创建首个会话、发送消息；没有 CLI 时也要给出安装或登录恢复路径。

### 用户能否从 UI 安装 Agent？

**不能。** UI 只能编辑 Registry 中已存在的 Agent。安装需要 Catalog、来源信息、兼容性检查、权限确认、执行/回滚、持久化和重启恢复；当前这些都不存在。

### Onboarding 是否顺畅？

**不存在完整 onboarding。** 当前首屏只让用户选择会话；如果 Agent 列表为空，不解释原因，也没有“重新检测”“去登录”“安装 Agent”或“导入配置”入口。

## 认知负担与断点

| 断点 | 用户需要猜什么 | 后果 | 优先级 |
|------|----------------|------|:---:|
| 首次使用必须编辑 TypeScript 配置 | CLI 命令、参数、输入模式、输出格式、模型名 | 非开发者直接流失；开发者也会试错 | P0 |
| 桌面 GUI 的 PATH 与终端可能不同 | 为什么终端能运行、应用却找不到 | 最常见的“明明装了但不可用”问题 | P0 |
| 无 Agent 时仍能创建空会话 | 为什么输入不可用、下一步去哪 | 形成死路空状态 | P0 |
| 只显示 online/error，不区分未登录 | 是没安装、没登录、命令错误还是版本不兼容 | 错误不可恢复 | P0 |
| Agent 设置只能编辑已有项 | 新 Agent 从哪里来 | “管理工具”心智不成立 | P1 |
| 会话管理只有创建/删除 | 历史如何找到、整理和带走 | 长期使用价值快速下降 | P1 |
| 群聊底层能力暴露为产品承诺 | 为什么创建不了群、不能加多个 Agent | 文档预期高于产品，伤害信任 | P1 |
| Relay Server 已有但客户端未接通 | 部署后为什么没有跨设备功能 | 自托管用户投入后无法获得结果 | P1 |

## 当前用户旅程 vs. 目标旅程

```text
当前：克隆仓库 → 安装依赖 → 安装并登录 CLI → 理解其非交互参数
     → 编辑 TS 配置 → 启动 → 排查 PATH/输出格式 → 才可能发送第一条消息

目标：安装应用 → 自动检测 → 选择可用 Agent → 发送第一条消息
                       └→ 未登录：给出一键打开终端的登录指引
                       └→ 未安装：打开 Agent 目录
```

## 产品决策

1. **先把单 Agent 做成优秀产品，再扩展群聊。** 群聊是核心愿景，但首条消息都不能低成本完成时，群聊不会被用户发现。
2. **配置文件降级为高级覆盖，不再是主入口。** 普通设置持久化到应用数据目录和数据库；配置文件用于团队策略、开发调试和可重复部署。
3. **“检测到”必须拆成状态。** 至少区分 `not_installed`、`installed`、`needs_auth`、`ready`、`unsupported`、`error`，每个状态提供明确动作。
4. **“安装”必须可解释、可撤销。** UI 必须展示来源、发布者、要执行的命令、所需权限和卸载方式，不允许静默执行任意 Catalog 命令。
5. **文档只承诺已闭环能力。** A2A、group 字段或 Relay API 可以标为“技术基础”，不能标成“用户已可使用群聊”。

## 发布门槛

v0.2 不应发布，除非同时满足：

- 支持清单内 CLI 的检测召回率达到 95%，误报率低于 1%。
- 新安装用户不编辑配置文件即可到达首条消息，p50 小于 60 秒。
- 没有 CLI、CLI 未登录、CLI 不兼容三种路径都有明确且可验证的恢复动作。
- UI 新增/启用的 Agent 重启后仍存在并能初始化。
- 无可用 Agent 时禁止创建死路会话，所有空状态只有一个清晰主行动按钮。
