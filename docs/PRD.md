# AgentLink — 产品需求文档 (PRD)

> 版本: v1.1 | 日期: 2026-07-31 | 作者: 张子涵

## 1. 产品概述

### 1.1 一句话定义

一个本地部署的、Agent 原生的即时通讯工具，支持人机对话（A2H）和 Agent 间通信（A2A），不受第三方平台限流。

### 1.2 解决的问题

| 痛点 | 现状 | AgentLink 方案 |
|------|------|---------------|
| 第三方 IM 限流 | 飞书 5条/秒，频繁通知被拒 | 本地部署，无频率限制 |
| Agent 之间无法直接通信 | 各 Agent 孤立，靠人转发 | 内置 A2A 消息总线 |
| Agent 接入分散 | 每个平台各自对接 | 统一 adapter 协议，即插即用 |
| 对话过程不透明 | Agent 调用链不可见 | A2A 对话线程可视化 |

### 1.3 目标用户

**核心用户：AI 应用开发者 & 技术团队**

- 开发者：需要一个不依赖第三方平台的 Agent 通信渠道，调试多 Agent 协作流程
- 技术团队：需要 Agent 之间能自主通信协作，不被人转发打断

> v0.1-0.2 聚焦单用户本地部署，多团队协作在 v0.3+ 规划。

### 1.4 核心价值

- **自主可控**：本地部署，数据不出机器
- **Agent 原生**：从协议层设计就为 Agent 通信优化
- **无限流**：自己控制消息频率
- **可视化**：Agent 间对话过程完整展示

## 3. 用户场景

> 以下场景描述产品完整愿景。MVP (v0.1) 仅实现单 Agent 流式聊天，多 Agent 协作场景需 v0.2+ 才能完整跑通。

### 3.1 场景一：多 Agent 代码审查

```
用户: 帮我审查这个 PR
  ↓
主 Agent 收到请求，通过 tool-calling 自主决策
  ↓
主 Agent → 调用 code-reviewer ──→ 返回 3 个问题
  ↓
主 Agent → 调用 security-checker ──→ 返回 1 个高危
  ↓
主 Agent 汇总结果 ──→ 回复用户
```

UI 上展示：Agent 间的调用链可展开查看，类似 Discord 线程。

### 3.2 场景二：日常 AI 助手

用户和自己的主 Agent 私聊，需要特定能力时提及对应 Agent：
- 写代码 → @code-agent
- 翻译 → @translate-agent  
- 搜索 → @search-agent

每个 Agent 有独立的对话上下文，互不干扰。

### 3.3 场景三：Agent 自动协作

用户发一条消息，主 Agent 通过 tool-calling 决定调用哪些 Agent：
```
用户: 今天的构建状态怎么样？
@main-agent → tool-calling → @build-monitor: "查最近构建状态"
@build-monitor: 最近 3 次构建全部成功
@main-agent → tool-calling → @metrics-agent: "查本周成功率"
@metrics-agent: 本周构建成功率 87%，比上周提升 5%
@main-agent: 汇总回复用户
```

> 决策机制：Agent 通过 LLM tool-calling 自主决定调用谁，不是无脑广播。

```
┌─────────────┬──────────────────────────────────────────┐
│  会话列表    │  私聊: 我的 Agent                         │
│             │                                          │

│ └─────────┘ │  [Agent] 好的，正在调用代码审查...         │
│ ┌─────────┐ │  ┌──────────────────────────────────┐   │
│ │👥构建群  │ │  │ 📋 A2A 调用链 (可折叠)             │   │
│ │          │ │  │ → @code-reviewer: 发现 3 个问题    │   │
│ └─────────┘ │  │ → @security-checker: 1 个高危     │   │
│             │  └──────────────────────────────────┘   │
│             │  [Agent] 汇总：共 4 个问题                │
│             │  ┌────────────────────────────────────┐  │
│             │  │ 输入消息...                    [发送]│  │
│             │  └────────────────────────────────────┘  │
└─────────────┴──────────────────────────────────────────┘
```

> 私聊是主入口，群聊在 v0.2 引入。MVP 阶段只有私聊。

### 4.2 消息类型

| 类型 | 说明 | 视觉 |
|------|------|------|
| 用户消息 | 用户发送 | 右侧气泡 |
| Agent 回复 | Agent 回复 | 左侧气泡 + 头像 |
| A2A 消息 | Agent 间通信 | 折叠卡片，可展开 |
| 系统消息 | 状态变更等 | 居中灰色文字 |
| 流式消息 | 正在生成 | 打字动画 + 逐字显示 |
| 错误消息 | Agent 报错/超时 | 红色提示卡片 |
| 部分消息 | 流式中断 | 黄色标记，保留已收内容 |

### 4.3 Agent 卡片

```
┌──────────────────────────┐
│ 🤖 Code Reviewer         │
│ 代码审查专家              │
│ ● 在线 | 模型: GPT-4o     │
└──────────────────────────┘
```

### 4.4 Agent 状态与错误处理

| 状态 | 说明 | UI 展示 |
|------|------|---------|
| online | 正常在线 | 绿色圆点 |
| offline | 未初始化/已销毁 | 灰色圆点 |
| busy | 正在处理消息 | 黄色圆点 + 动画 |
| error | 初始化失败/API 不可达 | 红色圆点 + 错误信息 |

Agent 离线时不接收消息，用户发消息给离线 Agent 时提示"Agent 当前不可用"。

## 5. 数据模型

### 5.1 核心实体

```
User (1) ──→ (N) Conversation
Conversation (1) ──→ (N) Message
Agent (1) ──→ (N) Message
Conversation (N) ←──→ (N) Agent (会话中的参与者)
Message (1) ──→ (0..N) Message (A2A 子消息)
```

### 5.2 消息结构

```typescript
interface Message {
  id: string;
  conversationId: string;
  fromType: "user" | "agent";
  fromId: string;
  toType?: "user" | "agent";
  toId?: string;
  content: string;
  timestamp: number;
  threadId?: string;        // A2A 线程
  parentId?: string;        // 消息回复链
  status: "sending" | "thinking" | "streaming" | "done" | "partial" | "error";
  metadata?: {
    model?: string;
    tokensUsed?: number;
    durationMs?: number;
  };
}
```

## 10. 跨设备与跨团队场景（FUTURE — v0.3+）

### 10.1 场景一：跨设备数据迁移

用户在聊天中让 Agent1 把本机数据整理后交接给另一台设备上的 Agent2：

```
用户: "@Agent1 把你电脑上的数据整理一下，交接给 @Agent2"
```

- Agent1 在子涵的 Mac 上执行：扫描数据 → 打包 → 上传到 Server 中转
- Server 通过 WebSocket 转发 A2A 调用到 Agent2 所在设备
- Agent2 在同事的 Mac 上执行：下载 → 解压 → 校验 → 回复完成
- Agent1 收到确认后回复用户

### 10.2 场景二：跨团队 Agent 协作

群聊中 Agent 自动排查问题，找到责任人并 @他的 Agent 修复：

```
群聊: 构建发布群

子涵: 帮我查一下构建为什么失败了
@zihan-agent: 读取日志 → 定位错误 → git blame → 找到小明
  → A2A 调用 @xiaoming-agent: "xxx.ts:42 你的代码有问题"
@xiaoming-agent: checkout → 修复 → commit → push
  → A2A 回复: "已修复，commit: abc123"
@zihan-agent: 重新构建 → 成功 → 群里回复
```

### 10.3 需要的扩展能力

| 能力 | 说明 | 优先级 |
|------|------|:---:|
| 用户系统 | 用户注册/登录，绑定自己的 Agent | P0 |
| Agent 目录 | userId → agentId → deviceId 映射 | P0 |
| 群聊会话 | 多人 + 多 Agent 共处一个会话 | P0 |
| 跨设备转发 | Server 作为中继，WebSocket 转发 A2A 调用 | P0 |
| 文件中转存储 | Agent 间文件传输 | P1 |
| 权限控制 | Agent 被调用时可选自动接受/需确认/拒绝 | P1 |
| 审批通知 | 敏感操作（改代码、push）需主人确认 | P1 |
| A2A 调用链展示 | 群聊中嵌套展示 Agent 间调用过程 | P2 |

## 11. 私聊为主、群聊为辅的交互模式（FUTURE — v0.2+）

### 11.1 核心理念

用户的日常入口是 **和自己的 Agent 私聊**（1对1），而不是群聊。用户在私聊中发现问题、讨论方案，需要涉及他人时让 Agent 代为出击到群聊。

### 11.2 交互流程

```
┌─────────────────────────────────────────────────────────┐
│  私聊界面 (你 ↔ 你的 Agent)                               │
│                                                         │
│  你: 刚才构建失败了，好像是小明提交的代码问题              │
│                                                         │
│  Agent: 我来看看... 确认了，xxx.ts:42 小明提交的代码      │
│         导致 TypeError。要我找他的 Agent 修吗？           │
│                                                         │
│  你: 去群里 @他                                         │
│                                                         │
│  Agent: 好的，已在构建群 @xiaoming-agent                  │
│  ┌─────────────────────────────────────┐                │
│  │ 📋 群聊任务追踪 (可展开)              │                │
│  │ → A2A 调用 @xiaoming-agent           │                │
│  │ → 等待回复中...                      │                │
│  │ → @xiaoming-agent: 已修复 abc123     │                │
│  └─────────────────────────────────────┘                │
│                                                         │
│  Agent: 小明的 Agent 已经修复了，我重新构建一下           │
│  Agent: ✅ 构建成功，问题已解决                           │
└─────────────────────────────────────────────────────────┘
```

### 11.3 设计要点

| 要点 | 说明 |
|------|------|
| **私聊是主场** | 日常开发、问问题、排查问题，都在和自己的 Agent 1对1 聊 |
| **Agent 代你出击** | 你说"去找谁解决"，Agent 自动在群聊中发起 A2A 调用 |
| **结果回到私聊** | 群聊中发生的事以可折叠卡片展示在私聊里，不用切到群聊 |
| **群聊是协作空间** | 群聊只在需要跨团队协作时使用，不作为日常入口 |
| **任务追踪卡片** | Agent 在群聊的操作实时以卡片形式回传私聊，可展开查看详情 |

### 11.4 消息类型扩展

私聊中嵌入"群聊任务追踪卡片"：

```
┌──────────────────────────────────────────┐
│ 📋 群聊任务: 修复构建失败                  │
│ 群聊: 构建发布群                          │
│ 状态: 🟢 已完成                           │
│                                          │
│ ▸ 调用链 (点击展开)                       │
│   ├─ 你 → @zihan-agent: "去群里@他"      │
│   ├─ @zihan-agent → 群聊: @xiaoming...   │
│   ├─ @xiaoming-agent: 修复中...          │
│   ├─ @xiaoming-agent: 已修复 abc123      │
│   └─ @zihan-agent: 重新构建 → 成功       │
│                                          │
│ [查看群聊原文]                            │
└──────────────────────────────────────────┘
```

### 11.5 场景示例

#### 日常开发

```
你: 帮我看看今天的构建状态
Agent: 今天构建了 5 次，4 次成功，1 次失败。
      失败的是 2 小时前的渠道包构建，错误是签名超时。
你: 重新构建一次
Agent: ✅ 已提交构建，正在运行...
```

#### 问题排查 → 跨团队协作

```
你: 上次的构建为什么失败了
Agent: 我查了日志，是 xxx.ts:42 的 TypeError，
      代码是小明 2 天前提交的。要我找他的 Agent 修吗？
你: 去群里 @他
Agent: 好的，已在构建群发起协作请求。
  ┌──────────────────────────────────┐
  │ 📋 群聊任务追踪                    │
  │ → A2A 调用 @xiaoming-agent        │
  │ → 等待回复中... (30s)             │
  └──────────────────────────────────┘
Agent: 小明的 Agent 已修复，commit: abc123。
      我重新构建了，✅ 构建成功。
```

#### 多步协作

```
你: 帮我发个版本，先构建，构建成功后上传 OSS
Agent: 好的，我来编排：
  ┌──────────────────────────────────────┐
  │ 📋 任务编排                           │
  │ ┌─────────────────────────────────┐ │
  │ │ Step 1: 构建 release-cn-signed  │ │
  │ │ ✅ 成功 (12分30秒)               │ │
  │ └─────────────────────────────────┘ │
  │ ┌─────────────────────────────────┐ │
  │ │ Step 2: 上传 OSS                │ │
  │ │ 🔄 上传中... 3/5 文件            │ │
  │ └─────────────────────────────────┘ │
  │ ┌─────────────────────────────────┐ │
  │ │ Step 3: 通知群聊 (待执行)        │ │
  │ └─────────────────────────────────┘ │
  └──────────────────────────────────────┘
```
